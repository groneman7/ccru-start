# Domain docs

## Read before exploring

This repo uses a single-context layout:

- `GLOSSARY.md` at the repo root defines domain vocabulary.
- `docs/adr/` contains architecture decisions. Read those relevant to the work.

If these files are absent, proceed silently. The domain-modeling skill
creates them as terms and decisions are resolved.

## Use domain vocabulary

Use glossary terms in issues, proposals, hypotheses, tests, and code.
Reconsider unfamiliar terms or note real vocabulary gaps for domain-modeling.

## Surface decision conflicts

When a proposal contradicts an ADR, identify the ADR and explain
why the decision should be reconsidered.
